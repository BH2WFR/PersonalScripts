# PDF Page Splitter

Run `../../pdf-page-splitter.py` or select `pdf-page-splitter` in the launcher.
The PySide6/Fusion GUI replaces the previous interactive CLI. Requires PySide6,
PyMuPDF and tqdm, already included in the project dependencies.

## Workflow

- Open or drop a PDF. The independent left column shows physical page number,
  displayed source dimensions and output paper dimensions, followed by two group boxes.
- **General** chooses 1–16 equal strips, left/right or top/bottom, output order,
  and the first/last physical page to split. Blank order uses spatial order from
  the left/top; an explicit permutation such as `3,1,2` can be reversed. Pages
  outside the selected range remain whole, unless they have an explicit override.
- **Current page** keeps a page whole or adjusts its crops. The combined **Crop**
  selector defaults to **All**, or selects a crop by its output-order number.
  X/Y edits and ±10 pt buttons move all frames or only that crop.
  A shared divider translates the chosen frames without changing
  their sizes. When independent crops no longer share an edge, use X/Y controls.
- Width/height resize the selected crop, or every crop for All. Each has ±10 pt
  buttons. All displays the first crop's values; typed sizes assign that dimension
  to every crop, while the buttons change each crop's existing dimension by 10 pt.
  All children of a split source page
  keep the same fixed paper dimensions. Smaller crops are centered at original
  scale, with blank margins. Crops may cross any source-page edge; missing source
  areas become blank, including a completely out-of-page crop. Crops cannot exceed
  their fixed output paper size. Coordinates use the displayed page's top-left
  origin, increasing right/down, in points (72 pt = 1 inch), independent of zoom.
- A first custom edit captures that page's crop order and paper size. Subsequent
  global changes leave those overrides intact. **Reset to general settings**
  removes the override. Temporarily keeping a custom page whole retains its crops
  so unchecking the option restores them. No covers are automatically skipped.
- The preview uses red, blue, green, brown, gray and additional colored outlines
  at 50% opacity, with large output-order numbers. Selected outlines are thicker.
  Overlays and numbers are never exported. **Show crops** hides them for inspection.
- Read-only **Pages / Bookmarks** navigate the source. The Processing column uses
  orange **不处理** for whole pages and blue **特殊处理** for explicit crops. The
  **Output start** column is the one-based physical index of the first output page
  generated by each source page, recalculated whenever splitting/ignore rules change.
- Reuse wheel zoom, drag panning, fit page/width, editable zoom, automatic page fit
  and focused PgUp/PgDn/arrow navigation. Settings commit on Enter/focus loss;
  movement buttons apply immediately. Geometry edits redraw only overlays.
- Hover over parameter labels or controls for purpose, scope and adjustment hints.
  They use the same window-scoped 250-pixel wrapping tooltip display as Binarize.
- Export defaults to `<source>_split.pdf` beside the input, with collision avoidance.
  Replacing an existing output requires confirmation; the source is protected even
  through another path to the same file. Unexported settings remain in memory only;
  closing/reopening prompts before discarding them. Active jobs finish before close.

## Export and preview ownership

Original PDF content is retained, including searchable text, vectors and shared scan
images. Ordinary in-bounds full-size crops use CropBox. Padding/reduced crops use
clipped Form XObjects and fixed page boxes, with no image recompression or rasterization.
Copied annotations are isolated before clipping appearances; copied widget references
retain their AcroForm registration. Visible links are clipped and their destinations
translated into output paper coordinates, including centered margins and rotation.
Metadata, XMP and embedded attachments are retained under the shared save policy.

All navigation page labels are removed, including on whole pages. Printed numbers
remain unchanged. Explicit XYZ bookmark targets follow the first crop containing
their point (output order resolves overlaps). Ambiguous targets go to the first
child page; their count and unsupported/unresolved links are reported after export.
Saving removes encryption and PDF/A identification using `utils.Pdf.save_new`.
Crops hide content outside the chosen view; this is not secure redaction.

One persistent QProcess owns all MuPDF calls on its main thread. Only one request
can run; navigation/settings lock while rendering/exporting, with a busy cursor.
Original preview misses render without a debounce delay. Cache hits are immediate,
within the common 512 MiB / 100-page budget. A shared RGB buffer avoids temporary
image files. No PDF object crosses into the GUI. Geometry and output paper sizes
remain independent of preview resolution, which uses the common bounded renderer.

The shared icon-and-text **Pause / Resume** and **Stop** buttons stay beside progress
in the bottom row, disabled when idle and enabled during export.
Pause waits for a safe processing boundary; the current page or save step may
finish first. Stop works while paused, removes incomplete output and restores
editing. Saving stages the PDF before publication, so cancellation during saving
keeps an existing destination intact. Settings stay locked until resumed/completed
or stopped. Brief previews remain uninterrupted.

| Module | Responsibility |
| --- | --- |
| `model.py` | Pure normalized crop geometry, equal output canvases and rule validation |
| `engine.py` | Resource-preserving crops/padding, annotations and destination remapping |
| `worker.py` | Serial authenticated inspection, rendering and safe export |
| `panel.py` | Two settings group boxes and committed coordinate edits |
| `viewer.py` | Colored numbered overlays on the shared viewer |
| `app.py` | Session rules, per-page state, output indexes, cache and window lifecycle |

Run `python -m unittest discover -s test -p "test_pdf_split_pages*.py"` through
the project's conda interpreter. Tests use generated PDFs and an offscreen Qt GUI,
including real worker transport, rotated crops, padding, annotations and navigation.
